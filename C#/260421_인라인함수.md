# 🧠 함수를 호출하지 않고 '기억'하는 인라인(Inline)함수

- '함수'를 호출하는 것은 비용이라는 말이 있다. 인라인은 그 비용을 제로로 만드는 기술이다.

----

1. **인라인(Inlining)이란?** 🔍
   
   - 인라인화는 컴파일러 함수를 호출하는 코드를 만났을 때, 함수 내부의 로직을 호출부로 직접 복사해 넣는 과정이다.
  
   💡  핵심 비유 => 일반적인 함수 호출이 궁금한 걸 전문가에게 전화해서 물어보는 것이라면, 인라인은 그 지식을 내 머릿속에 완전히 넣어두었다가 **필요할 때 바로 떠올리는 것**과 같습니다.

----

1. **왜 인라인이 성능에 좋을까?** ⚡
   
   단순히 두 수를 더하는 함수 Add(a,b)가 있다고 가정해보자. 이 함수를 수만 번 호출한다면 다음과 같은 낭비가 발생한다.
   - 오버헤드 : 매개변수 전달, 복귀 주소 저장, 점프 연산 등 '준비 과정'이 실제 더하기 연산보다 더 많은 에너지를 쓴다.
   - 흐름 단절 : CPU가 코드를 읽다가 다른 메모리 주소로 점프해야 되므로 명령어 파이프라인의 효율이 떨어진다.

    인라인화가 되면 이 모든 준비 과정이 사라진다. 컴파일러는 Add(a,b)를 그냥 a+b라는 로직 그 자체로 대체해 버린다. CPU는 멈춤 없이 사고의 흐름을 이어갈 수 있다.

----

3. **C#에서 인라인을 제어하는 방법** 🛠️

    C#의 JIT(Just-In-Time) 컴파일러는 아주 짧은 함수는 알아서 인라인화합니다. 하지만 개발자가 명시적으로 "이건 꼭 인라인해줘!"라고 힌트를 줄 수도 있습니다.
    ```c++
    using System.Runtime.CompilerServices;

    // 1. 강제 인라인 힌트 (AggressiveInlining)
    [MethodImpl(MethodImplOptions.AggressiveInlining)]
    public int FastAdd(int a, int b)
    {
        return a + b;
    }

    // 2. 인라인 방지 (NoInlining) - 디버깅이나 특수 상황에서 사용
    [MethodImpl(MethodImplOptions.NoInlining)]
    public void CriticalLog()
    {
        // 로직
    }
    ```

----

4. **언제 사용하면 좋을까?** ✅
   
    - 함수 본문이 매우 짧을 때: 한두 줄짜리 단순 계산이나 Getter/Setter.

    - 루프(Loop) 내부에서 반복 호출될 때: 수만 번 돌아가는 for문 안의 함수는 인라인의 효과가 극대화됩니다.

    - 성능이 최우선인 로직: 게임 엔진의 물리 연산, 수학 라이브러리 등.

----

5. **주의할 점** ⚠️
    - 코드 비대화(Code Bloat): 모든 호출부에 코드를 복사해 넣으면 바이너리 크기가 커집니다.
    - 캐시 효율 저하: 코드가 너무 길어지면 CPU의 작은 'L1 캐시'에 다 담기지 않아 오히려 속도가 느려질 수 있습니다.
